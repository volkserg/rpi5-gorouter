# Изменения volkserg.rpi5_gorouter

Версия коллекции совпадает с версией routerd, которую роль ставит по умолчанию.

## Не выпущено

- Веб-интерфейс:
  - приветствие — при открытии панели (не при обновлении страницы и не
    сразу после ввода пароля) замок сам открывается, затем панель;
  - «Проверить» в строках «Обращений» (столбец исходов) — подставляет
    ресурс и порт строки;
  - строки «Обращений» и надпись «Проверить» больше не подрагивают при
    наведении.

## 0.4.9

- Веб-интерфейс: убраны артефакты отрисовки — мерцающий квадрат фоновой
  подсветки, дрожащая линия у кнопки «Войти», «залипшая» подсветка строк
  после обновления списка. Обычные карточки больше не размывают фон под
  собой (под ними только фон), подсветка в панели неподвижна, на странице
  входа «дышит» без отдельного слоя (анимация градиента через @property).

## 0.4.8

- Веб-интерфейс, «Обращения»: полоска слева у строки — цвет исхода
  последнего соединения (зелёная — проблемы были, но последнее удалось);
  отказ или сброс — рыжий, туннель без данных — бежевый; обновлённые строки
  подсвечиваются нейтральным голубым, а не зелёным.

## 0.4.7

- Веб-интерфейс, кандидаты в VPN: «Свернуть» из глубины длинного списка
  «втягивает» его — экран едет вверх вместе с нижней границей блока, пока
  список сжимается; подсветка рамки начинается сразу и к концу гаснет.
- Веб-интерфейс: блок с паузой больше не «улетает», если быстро прокручивать
  туда-обратно на границе его всплытия.

## 0.4.6

- Веб-интерфейс: «Свернуть» у кандидатов надёжно возвращает к началу блока
  (прокрутку больше не прерывает подстройка браузера после сворачивания
  длинного списка) и коротко подсвечивает рамку блока.
- Демо (`testbed/webdemo`): при запуске сразу много кандидатов в VPN.

## 0.4.5

- Веб-интерфейс, «Обращения»:
  - пауза, «обновить сейчас» и новая кнопка «к фильтрам» при прокрутке
    прилипают к верху экрана над своим местом (плавно переезжают туда и
    обратно);
  - «Показать все / Свернуть» у кандидатов — в шапке блока, при прокрутке
    длинного списка тоже прилипает; «Свернуть» возвращает к началу блока;
  - круглые кнопки на телефоне больше не сплющиваются.

## 0.4.4

- Веб-интерфейс, «Проверка»: кому может принадлежать адрес — сеть и
  название оператора (номер автономной системы, страна), обратное имя
  (PTR), сертификат сервера (на кого выписан, для IP — без SNI), имена, под
  которыми устройства LAN получали этот адрес в DNS-ответах, и имена из TLS
  при обращениях по IP.
- «Обращения»: ресурсы, к которым устройство обратилось по IP без запроса к
  DNS routerd, помечены «по IP» (домен в списке VPN такие соединения не
  завернёт — нужен IP или подсеть) и получают подсказку — имя сайта из TLS
  ClientHello (SNI); пояснение — в облачке по кнопке «без DNS». Первые
  пакеты каждого соединения TCP с LAN ядро
  копирует routerd через NFLOG (цепочка `prerouting_sni`; нужен модуль
  `nfnetlink_log`, без него не работает только подсказка). Работает, когда
  включён учёт обращений.
- Имена IP-адресов: проверка IP записывает в память лучшее имя (из
  сертификата сервера, иначе PTR, иначе оператор сети), и в «Обращениях» у
  адреса появляется плашка «≈ имя». Имя можно поправить или забыть (заданное
  вручную проверка не меняет), кнопка «Забыть имена адресов» стирает все
  сразу. Хранятся в `/var/lib/routerd/ip_labels.json`.
- «Обращения»: пауза автообновления и кнопка «обновить сейчас» рядом с «в
  реальном времени» (при прокрутке списка они плавают в углу экрана);
  переключатель «Компактно | Развёрнуто» и стрелка у строки — подробности
  целиком, без обрезки.
- Роль: факты — через `ansible_facts[...]`; ansible-core больше не
  предупреждает о прекращении подстановки фактов `ansible_*` (2.24).

## 0.4.3

- Веб-интерфейс:
  - «Журнал» на телефоне — по ширине экрана (страница больше не уезжает
    вбок), запись: время и уровень строкой, текст с переносом;
  - журнал Pi-hole — из `/var/log/pihole/FTL.log` (в journald Pi-hole почти

  - «Кандидаты в VPN»: показаны первые 3, остальные по кнопке; по счётчику

  - «Устройства»: своё имя устройства (хранится в
    `/var/lib/routerd/device_names.json`), видно и в «Обращениях»;
  - кольцо загрузки на кнопках больше не перекрывает текст.

## 0.4.2

- Веб-интерфейс, «Журнал»: показывался только время и уровень записи, без
  текста — исправлено. routerd читает журнал с `journalctl -o json --all`
  (все поля записи целиком).

## 0.4.1

- Веб-интерфейс открывается и по имени `<хост>.local`: имя добавлено в
  сертификат, интерфейс слушает и IPv6 (mDNS часто отдаёт его первым).
  Соединения принимаются только из LAN, подсетей локальных сервисов,
  link-local и ULA IPv6.

## 0.4.0

- Веб-интерфейс (`WEB_UI=yes`, порт `WEB_PORT`, по умолчанию 8443): панель
  по HTTPS с самоподписанным сертификатом, вход по логину и паролю
  (`routerd web passwd`), «запомнить устройство» на 30 дней. Сервис
  `routerd-web.service` работает от пользователя `routerd-web` без прав.
  Разделы: обзор (состояние туннеля, режим, размеры списков); список VPN —
  поиск, добавление и удаление, скачивание файла, импорт «добавить к
  текущему» или «заменить» с предпросмотром разницы; редактор
  `dns_override.txt` с проверкой перед сохранением. Изменения применяются
  сразу, в журнале routerd — кто их сделал.
- Обращения устройств (`ACCESS_HISTORY_DAYS`, по умолчанию 7 суток; 0 —
  выключено): по каждому устройству и ресурсу — успешные соединения,
  таймауты, отказы и соединения через туннель без данных, маршрут
  (напрямую или через туннель). Ресурс назван по DNS-ответам routerd,
  устройство — по аренде DHCP. Ресурсы, которые напрямую не отвечают, —
  «кандидаты в VPN»: добавляются в список одной кнопкой. История — на RPi
  в `/var/lib/routerd/history`.
- Обзор: состояние сервисов стека; внешний адрес RPi и выхода туннеля со
  временем ответа (`TUNNEL_CHECK_URL`, по умолчанию `https://api.ipify.org`,
  `none` — без проверки).
- «Проверка»: RPi соединяется с ресурсом напрямую и через туннель (для
  порта 443 — с TLS-рукопожатием), запрашивает страницу и подсказывает,
  нужен ли ресурс в списке VPN — в том числе когда напрямую сервер отвечает
  отказом в доступе (HTTP 403/451), а через туннель — нет.
- «Устройства»: аренды DHCP, сервисы RPi и адреса без аренды с итогами
  обращений за сутки. «Журнал»: записи routerd, веб-интерфейса, клиента
  туннеля, Pi-hole и dnscrypt-proxy в реальном времени.
- Роль: `routerd_web_users` — пользователи веб-интерфейса (добавление и смена
  пароля); `routerd-web.service` включается и запускается по `WEB_UI`.

## 0.3.2

- routerd: `add-vpn-domain` и `remove-vpn-domain` действуют сразу и на адреса,
  которые устройства уже держат в своих DNS-кэшах: routerd помнит недавние
  DNS-ответы и сам добавляет или убирает их адреса в `vpn_dynamic`. Раньше
  добавленный домен начинал идти в туннель только после повторного
  DNS-запроса устройства, а удалённый — уходил из туннеля только через
  `VPN_DYNAMIC_TIMEOUT`.

## 0.3.1

- `router.conf` из `routerd_conf`: значения берутся в кавычки shell, где
  нужно. Раньше `LOCAL_CLIENTS` с несколькими сервисами (пробел в значении)
  не проходил проверку `check-config`, и роль останавливалась.

## 0.3.0

- routerd: сервисы на самой RPi как клиенты LAN — `LOCAL_CLIENTS`, шаблон
  `routerd-local@.service` (роль и `install.sh` его ставят), пример юнита
  `deploy/systemd/local-app.service`.
- routerd: в режиме route туннель восстанавливается после быстрого (быстрее
  2 с) перезапуска GOST — раньше маршрут в новый tun не возвращался.
- routerd: имена без точки отвечаются из зоны `lan` (или NXDOMAIN), а не
  зацикливаются через Pi-hole.

## 0.2.3

  `.local` — сразу NXDOMAIN.
